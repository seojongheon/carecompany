# 역할 기반 대시보드 내비게이션 설계

## 목표

공개 홈페이지 헤더의 로그인 항목을 인증 상태와 계정 역할에 맞게 변경한다. 데스크톱 헤더와 모바일 메뉴에서 동일한 동작을 제공한다.

## 범위

- 비로그인 사용자는 기존과 동일하게 `로그인` 링크를 본다.
- 활성 관리자 또는 슈퍼 관리자 세션은 `대시보드` 링크를 보며 `/admin`으로 이동한다.
- 고객 세션은 `대시보드` 버튼을 보지만 아직 고객 대시보드가 없으므로 이동 경로를 연결하지 않는다.
- 고객용 버튼은 비활성화하고 보조 설명으로 `고객 대시보드 준비 중`을 제공한다.
- 고객 대시보드 페이지 생성, 로그아웃 UI 변경, 인증·권한 모델 변경은 포함하지 않는다.

## 구성 요소

`CustomerAuthNav`가 `AuthProvider`의 현재 세션을 읽어 세 가지 상태를 렌더링한다.

| 세션 상태 | 표시 | 요소 | 이동 |
| --- | --- | --- | --- |
| 없음 | 로그인 | 링크 | `/login` |
| `admin`, `super_admin` | 대시보드 | 링크 | `/admin` |
| `customer` | 대시보드 | 비활성 버튼 | 없음 |

기존 `Header`와 `MobileMenu`가 같은 `CustomerAuthNav`를 사용하므로 별도 역할 분기 없이 두 화면에 동일하게 반영한다.

## 데이터 흐름

1. `AuthProvider`가 Supabase 인증 세션과 프로필 역할을 저장한다.
2. 세션 변경 시 `CustomerAuthNav`가 다시 렌더링된다.
3. 역할에 따라 로그인 링크, 관리자 대시보드 링크, 고객용 비활성 버튼 중 하나를 출력한다.
4. 로그아웃 또는 세션 만료로 세션이 사라지면 로그인 링크로 복귀한다.

## 접근성 및 오류 처리

- 고객용 대시보드는 실제 `<button disabled>`로 출력해 링크처럼 오인하거나 키보드로 실행되지 않게 한다.
- `aria-label` 또는 동등한 접근성 이름으로 준비 중 상태를 알린다.
- 모바일과 데스크톱에서 기존 높이, 여백, 글꼴 스타일을 유지한다.
- 알 수 없는 역할은 타입 수준에서 허용하지 않으며, 세션이 없을 때와 같은 로그인 상태로 안전하게 처리한다.

## 테스트

- 비로그인 상태에서 `로그인` 링크가 `/login`을 가리키는지 검증한다.
- 고객 상태에서 `대시보드`가 비활성 버튼이며 링크가 아닌지 검증한다.
- 관리자와 슈퍼 관리자 상태에서 `대시보드` 링크가 `/admin`을 가리키는지 각각 검증한다.
- 모바일 변형에서도 동일한 역할별 동작과 스타일 분기가 유지되는지 검증한다.
- 전체 단위 테스트, 타입 검사, 린트를 실행한다.

## 완료 조건

- 로그인 직후 세션 역할에 따라 헤더 버튼이 즉시 변경된다.
- 관리자 계정은 `/admin`으로 이동할 수 있다.
- 고객 계정은 대시보드 버튼을 볼 수 있으나 어떤 경로로도 이동하지 않는다.
- 비로그인 상태의 기존 로그인 흐름이 유지된다.

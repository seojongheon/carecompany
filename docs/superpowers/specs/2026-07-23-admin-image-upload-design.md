# 관리자 이미지 업로드 설계

## 목표

관리자가 사례 사진과 랜딩 히어로 대표이미지를 드래그앤드롭 또는 로컬 파일 선택으로 준비·검증·미리보기·저장·게시할 수 있게 한다.

## 사용자 흐름

1. 관리자는 사례 편집 화면에서 사진을 드롭하거나 파일을 선택한다.
2. 시스템은 파일 형식, 20MB 용량, 사례당 69장/회당 20장 제한과 권장 비율을 즉시 안내한다.
3. Storage가 비활성일 때는 미리보기와 메타데이터 준비만 하고, 실제 저장 전 상태임을 명시한다.
4. Storage가 활성화되면 같은 UI로 원본을 업로드하고 사례 미디어 목록에 반영한다.
5. 관리자는 홈페이지 관리 화면에서 랜딩 히어로 이미지를 선택하고 대체 텍스트를 입력한 뒤 초안 저장·게시한다.

## 구성

- `ImageDropzone`: 클릭, 드래그앤드롭, 키보드 접근, 안내 문구, 권장 비율 경고를 담당한다.
- `UploadPanel`: 사례별 다중 이미지 준비와 Storage 상태를 담당한다.
- `LandingHeroImageManager`: 히어로 단일 이미지 준비, 대체 텍스트, 초안 콘텐츠 반영을 담당한다.
- 콘텐츠 모델: `heroImageUrl`과 `heroImageStoragePath`를 선택적으로 보관한다. URL이 있으면 공개 랜딩 히어로가 그 이미지를 사용하고, 없으면 기존 목업을 유지한다.
- Storage: 비활성 상태를 유지한다. 활성화 시 전용 사이트-이미지 경로를 포함한 게이트웨이로 실제 저장을 연결한다.

## 권장 이미지

| 위치 | 권장 크기 | 비율 | 형식 |
| --- | --- | --- | --- |
| 사례 사진 | 1600 × 1200px | 4:3 | JPG 또는 WebP |
| 랜딩 히어로 | 1920 × 1080px | 16:9 | JPG 또는 WebP |

권장 비율과 다르면 업로드를 막지 않고, 공개 영역에서 잘릴 수 있다는 경고를 표시한다.

## 보안·오류 처리

- 실제 Storage는 `NEXT_PUBLIC_SUPABASE_STORAGE_ENABLED=true`일 때만 사용한다.
- Storage가 꺼진 상태에서는 원격 저장 성공처럼 표시하지 않는다.
- 허용 이미지 형식, 파일당 20MB, 사례당 수량 제한을 재사용한다.
- 대체 텍스트 없이 히어로 이미지를 게시하지 않는다.
- 공개 랜딩에는 공개 URL만 사용한다. 원본 경로는 공개 화면에 노출하지 않는다.

## 테스트

- 드래그앤드롭과 로컬 파일 선택이 같은 검증 흐름을 사용한다.
- 권장 비율과 제한 안내가 보인다.
- Storage 비활성 상태에서는 실제 저장 대신 준비 상태를 보인다.
- 히어로 URL이 있을 때 랜딩이 실제 이미지를 사용하고, 없을 때 기존 목업을 사용한다.

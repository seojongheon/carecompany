현재 관리자/Figma 구현을 기준으로 연결된 Supabase의 실제 데이터와 처리 구조를 22:40–22:56 KST에 재검증했다. 계획은 `specs/011-admin-data-integrity/`에 있으며 기존 009/010 계약은 보존했다.

- 필수 문서 누락 0. 문서 19개, 문서 이력 8개.
- 설정을 포함한 현재 초안·공개 JSON 모두 화면 기본값 보충 전 스키마 검증 통과. 이전 설정의 필수 필드 누락은 해소됐다.
- 사례 초안 52개·사례 이력 10개가 DB manifest 검증 통과. revision/사례 ID/상태 불일치 0, 비공개 사례의 초안 누락 0.
- 서비스/가격 공개 문서와 투영 테이블의 누락·추가·내용 불일치 0.
- 미디어 등록 누락 0, 등록 자산의 실제 객체 누락 0, 검사한 사례·문서의 파일 경로 누락 0.
- Auth 회원과 profiles 연결 누락 0, 활성 최고관리자 1명.
- 모든 인덱스 유효. 조회 지연 근거 없이 추가 인덱스를 늘리지 않았다.

## 적용 전후 보존

실제 콘텐츠 복제본을 격리 PostgreSQL에 적재해 이관을 먼저 연습했다. 설정/가격 외 문서 17개, 게시 이력 8개, 공개 가격 4개가 동일하며 반복 적용해도 추가 변경이 없음을 확인했다.

실제 적용 전 34개 앱 테이블의 행 수/내용 지문과 대상 문서 원본, 버킷 5개 설정을 로컬 비공개 파일에 보관하고 적용 후 대조했다.

- 전체 34개 테이블 행 수 동일.
- content_documents 외 33개 테이블의 전체 행 지문 동일.
- content_documents는 settings/pricing 2개만 변경. 다른 17개 문서 동일.
- 기존 설정의 모든 키 값 보존. 가격 공개본과 가격 테이블 동일.
- 버킷 5개의 공개 여부·MIME·용량 제한 동일, 모두 private.
- seed, 데이터 초기화, 파일 삭제, 정책 게시, Storage 활성화 없음.

## 남은 운영 입력과 범위

사업자·대표자·연락처·주소 등 실제 정보는 아직 입력되지 않은 값이며 추측해 채우지 않았다. 개인정보/문의 동의 정책은 미검토·미게시 상태라 문의 접수는 계속 차단된다. 정책을 준비한 뒤 최고관리자가 검토·게시해야 한다. 외부 알림 미연결과 스토리지 활성화 설정도 그대로다.

운영에서 가격을 시험 게시하거나 파일을 업로드하지 않았다. 게시·복원·충돌·롤백은 실제 PostgreSQL 기반 격리 환경에서 검증했다. 이 DB 보완 이후 사용자 요청으로 동일 코드 `1c0daaf`를 Vercel 운영에 배포했다. 재확인한 DB dry run은 최신 상태이며, 실제 운영 관리자 화면의 가격 4개 항목과 설정 revision 3을 PC·모바일에서 검증했다. 배포·조회 검증 상세는 `admin-figma-refresh.md`의 후속 운영 배포 절에 기록했다.

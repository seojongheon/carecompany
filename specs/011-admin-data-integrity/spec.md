# Feature Specification: 관리자 데이터 정합성 보완

**Feature Branch**: `codex/admin-operations`
**Created**: 2026-10-23
**Status**: 실행 요청에 따른 확정 범위
**Input**: 수정된 관리자 시스템을 기준으로 Supabase 데이터 누락과 처리 구조를 재점검하고 필요한 계획·수정까지 수행한다.

## User Scenarios & Testing

### User Story 1 - 이관된 편집 데이터를 빠짐없이 사용 (Priority: P1)
운영자는 공통 설정과 가격표를 열었을 때 기존 내용을 유지하면서 모든 새 항목을 편집할 수 있다.
**Independent Test**: 이전 형식의 설정과 최초 이관된 빈 가격 초안에 보완을 적용해 공개 가격·기존 입력·다른 문서가 보존되는지 확인한다.
**Acceptance Scenarios**:
1. 기존 설정에 확장 필드가 없으면 기존 값은 유지하고 미입력 정보는 빈 값으로 보충한다.
2. 운영자 수정 없이 최초 이관에서 누락된 가격 초안만 현재 공개 가격으로 복구한다.
3. 운영자가 의도적으로 비운 가격 초안은 복구 대상으로 처리하지 않는다.

### User Story 2 - 반복 게시·복원 시 가격 항목 식별 유지 (Priority: P1)
가격 항목은 초안·공개 문서·가격 목록에서 같은 항목으로 식별되어야 한다.
**Independent Test**: 이전 형식의 항목 식별자를 게시하고 다시 게시·복원해 값과 연결 관계를 확인한다.
**Acceptance Scenarios**:
1. 이전 형식의 식별자는 게시 때 일관된 식별자로 전환하고 다음 게시부터 유지한다.
2. 동시 수정과 오류는 원자적으로 거부하고 기존 공개본을 보존한다.

### Edge Cases
- 기존 필드가 빈 값이어도 사용자의 값으로 보존한다. 없는 키만 추가한다.
- 공개되지 않은 문서를 보완한다는 이유로 게시하지 않는다.
- 이전 게시 이력과 운영 감사 기록은 원본 그대로 보존한다.
- 서비스 식별자는 네 종류로 고정한다. 잘못된 자동 기본값을 새 환경에 재현하지 않는다.

## Requirements
- **FR-001**: 스키마뿐 아니라 필수 문서, 사례 초안/이력, 미디어 경로, 회원 연결, 가격·서비스 공개 투영을 실제 데이터로 대조한다.
- **FR-002**: 보충은 누락된 필드와 변경 이력으로 입증되는 최초 이관 누락에 한정한다. 사업자·연락처·정책 문안을 추측하지 않는다.
- **FR-003**: 보완된 문서는 버전을 올려 이미 열린 편집 화면의 조용한 덮어쓰기를 방지한다.
- **FR-004**: 가격 게시 후 문서와 가격 목록의 식별자·금액·조건·표시·순서가 일치해야 한다.
- **FR-005**: 역할, 공개 상태, 저장 경로, 미수정 문서, 문의, 감사 기록을 보존한다.
- **FR-006**: 실제 적용 전 격리된 데이터 복제본에서 이관을 검증하고 dry run으로 적용 범위를 확인한다.

### Key Entities
공통 설정, 가격 문서의 초안/공개본/이력, 공개 가격 항목, 서비스 고정 식별자, 사례·미디어 참조.

## Success Criteria
- **SC-001**: 이관 누락 가격 초안에 기존 공개 항목 4개가 나타나며 공개 가격 내용은 변하지 않는다.
- **SC-002**: 공통 설정은 화면의 임시 보충 없이 모든 현재 필드 검증을 통과한다.
- **SC-003**: 반복 가격 게시·복원 후 항목 식별 불일치가 0개다.
- **SC-004**: 보완 대상 외 운영 데이터와 저장소 설정의 변경이 0개다.

## Assumptions
현재 연결된 운영 프로젝트 사용은 이미 승인되었다. 새 기능 추가나 운영 정책 게시, 저장소 활성화, 데이터 초기화는 범위가 아니다. 기존 009/010 계약은 보존하고 이 보완만 011에 기록한다.

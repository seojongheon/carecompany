# 관리자 Figma 구현 계획

## 근거와 기술

명세: `spec.md`, 디자인 전달 문서 및 실제 Figma 고해상도 문맥. Next.js16/React19/TypeScript/Tailwind4/Radix/Lucide와 기존 Supabase 경계를 재사용한다. 새 의존성은 필요하지 않다.

## 구조

- `components/admin/`: 공통 페이지 헤더·탭·상태/카드, 밝은 탐색, 계정 메뉴, 대시보드 업무 우선 배치.
- `features/portfolio/ui/`: 기존 폼 상태를 유지하는 섹션 탐색과 편집·게시 작업 영역, 목록 상태 탭. 기존 미디어/영상/태그/복원은 모두 노출한다.
- `features/site-content/ui/`: 문서별 그룹과 보조 저장·검토 패널, 실제 문서 탭과 공지 목록, 서비스 선택 상태를 URL에 보존한다. 재귀 필드 편집기를 재사용해 필드 누락을 막는다.
- `app/admin/(protected)/`, 문의/회원/미디어/알림: 공통 화면 언어와 목록·카드·상세 배치를 적용한다.
- `app/admin/admin.css`: 관리자 내부에만 적용되는 토큰·폼·반응형 규칙. 고객 화면 전역 스타일은 변경하지 않는다.

## 대안과 결정

전체 데이터 계층 재작성은 검증된 권한·게시 경계를 위험하게 하므로 제외한다. CSS 덧씌우기만으로는 업무 우선순위·탭·편집 구조를 표현할 수 없어 공통 컴포넌트와 화면별 JSX를 함께 수정한다. 디자인은 사용자가 지정한 완성 Figma를 따른다.

## 계약·데이터·이관

기존 서버 함수와 Repository 인터페이스 및 `009` DB 계약을 유지한다. 화면 상태는 URL 또는 지역 상태, 영속 초안은 기존 서버 저장으로 구분한다. DB 담당 점검에서 결함이 입증되면 별도 회귀검증과 비파괴 migration을 추가한다. 기존 기록·비공개 bucket 보존.

## 검증과 검토 주의점

새 탐색이 입력을 버리지 않는지, 작은 화면에서 모든 필터가 열리는지, 최고 관리자 메뉴가 일반 운영자에게 나타나지 않는지, 데이터 없음/실패가 숫자0으로 바뀌지 않는지, 게시/삭제가 일반 화면 전환으로 실행되지 않는지 확인한다. `pnpm test`, `pnpm typecheck`, `pnpm lint`, `pnpm build`, DB isolated checks, Playwright 및1440/390 캡처를 실행한다.

헌장 검토: 서비스4종/역할/실제 데이터/44px/비공개/초안 게시 경계 유지. 새 외부 라이브러리와 정책 문안 추가 없음.

# 관리자 Figma 화면 재구성

2026-10-23 사용자 구현 요청에 따른 실행 명세. 승인된 `009-admin-operations`의 기능 계약과 `docs/design/admin-figma/01-admin-ui-ux-brief.md`, Figma `rdCv6zt7qIe1kWIyBd0Wh0`를 계승한다. 기존 명세는 대체하지 않는다.

## 사용자 시나리오

- US1 (P1): 운영자는 홈과 같은 밝은 브랜드 화면에서 9개 메뉴를 찾고, 문의와 게시 업무를 먼저 확인한다. 모바일 메뉴는 선택 후 닫히고 현재 위치를 표시한다.
- US2 (P1): 운영자는 문의·사례의 모든 기존 검색, 필터, 편집, 검토, 게시, 복원 기능을 새 화면에서 사용할 수 있다.
- US3 (P1): 운영자는 서비스·가격·콘텐츠를 영역별로 편집한다. 문서 선택, 폼 그룹, 저장·미리보기·비교·이력이 구분되고 모든 기존 필드는 유지된다.
- US4 (P2): 최고 관리자는 회원·권한·운영 설정·활동 기록을 관리하고, 운영자는 미디어·방문 통계의 기존 정보를 조회한다.

## 요구사항과 수용 기준

1. 구현 전에 기존 화면과 Figma 간 대응표를 작성한다. Figma에 축약된 필드나 기능은 같은 디자인 언어로 보완한다.
2. 데스크톱 240px 밝은 사이드바, 72px 상단바, 32px 본문 여백, 32/42 제목, 파란 선택 상태, 16px 카드 모서리를 따른다. 모바일 390px에서는 16px 여백과 한 열 폼을 사용한다.
3. 기존 9개 메뉴·URL·역할 제한·로그인 후 홈 이동을 유지한다. 샘플 수치나 디자인 예시 고객을 운영 데이터로 넣지 않는다.
4. 초안 저장·게시·개인정보 검토·수정 충돌·삭제함·복구 및 원본/공개본 경계를 유지한다. 새 탭이나 접기 영역에서 입력 상태가 사라지지 않는다.
5. 문의 검색/전체 상태/서비스/경로/담당자/기간/정렬/읽지 않음, 사례 모든 필터/태그/SEO, 문서 모든 필드, 미디어 실패·정리, 회원 검색·사유, 설정 권한 이력, 통계 캠페인을 모두 유지한다.
6. 390px와1440px에서 가로 넘침 없이 사용하고, 최소44px 조작 영역·키보드 포커스·문자 상태를 제공한다.
7. 연결된 Supabase는 실제 이관 상태와 권한을 확인한다. 검증된 결함이 있을 때만 데이터 보존형 이관을 추가한다. 초기화·seed·스토리지 공개 전환은 하지 않는다.

## 경계와 가정

사용자가 완성된 Figma를 구현 기준으로 지정했으므로 새 시안 선택을 요구하지 않는다. 긴 실제 폼은 Figma의 축약 예시보다 높아질 수 있으며 고정 높이로 자르지 않는다. 조회/변경은 기존 신뢰된 서버·저장소를 사용한다. 화면 재구성만으로 신규 DB 엔터티를 만들지 않는다.

## 성공 기준

- 대응표의 모든 기존 기능이 새 화면에서 접근 가능하다.
- 9개 메뉴의390px/1440px 화면과 주요 편집 흐름이 검증된다.
- 기존 회귀 테스트 및 새 탐색·폼 보존 테스트가 통과한다.
- 실제 DB 검증 범위와 미검증 범위를 구분해 기록한다.

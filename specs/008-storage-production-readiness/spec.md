# Feature Specification: 운영 이미지 Storage 활성화

**Feature Branch**: `main`

**Created**: 2026-08-05

**Status**: Approved

**Input**: 사례 이미지와 랜딩 대표 이미지의 업로드 제한, 접근 정책, 삭제 정합성 및 배포 준비를 완료하여 운영 환경에서 이미지 저장을 활성화한다.

## User Scenarios & Testing

### User Story 1 - 관리자가 사례 이미지를 안전하게 저장한다 (Priority: P1)

활성 관리자는 사례 편집 화면에서 허용된 이미지를 업로드하고, 원본과 공개 검토본을 분리해 저장하며, 새로고침 후에도 저장 결과를 확인할 수 있다.

**Why this priority**: 사례 이미지는 포트폴리오의 핵심 콘텐츠이며 원본 보호와 공개 범위가 동시에 보장되어야 한다.

**Independent Test**: 활성 관리자, 일반 사용자, 비로그인 방문자로 각각 업로드와 조회를 시도해 역할과 공개 상태에 따른 결과를 확인한다.

**Acceptance Scenarios**:

1. **Given** 활성 관리자가 로그인한 사례 편집 화면, **When** 허용된 이미지를 업로드하면, **Then** 원본과 검토본이 분리 저장되고 사진 정보가 사례에 연결된다.
2. **Given** 비활성 관리자·일반 고객·비로그인 방문자, **When** 원본 또는 검토본을 업로드·변경·삭제하려 하면, **Then** 요청이 거부된다.
3. **Given** 비공개 사진 또는 비공개 사례, **When** 방문자가 사진을 조회하려 하면, **Then** 사진 주소를 발급받지 못한다.
4. **Given** 공개 승인된 사진이 게시 사례에 연결됨, **When** 방문자가 사례를 조회하면, **Then** 제한 시간 동안 유효한 검토본만 표시된다.

---

### User Story 2 - 관리자가 랜딩 대표 이미지를 게시한다 (Priority: P1)

활성 관리자는 랜딩 대표 이미지를 업로드해 초안에서 확인하고, 콘텐츠를 게시한 뒤에만 방문자에게 노출할 수 있다.

**Why this priority**: 현재 대표 이미지 입력은 미리보기에 머물러 있어 Storage 활성화 시 사용자 안내와 실제 동작이 일치하지 않는다.

**Independent Test**: 대표 이미지를 업로드한 뒤 게시 전·후의 공개 화면을 비교하여 게시 전에는 기존 이미지, 게시 후에는 새 이미지가 표시되는지 확인한다.

**Acceptance Scenarios**:

1. **Given** 활성 관리자, **When** 허용된 대표 이미지를 선택하면, **Then** 실제 저장 완료 상태와 미리보기가 표시되고 초안에 저장 경로가 기록된다.
2. **Given** 새 대표 이미지가 초안에만 있음, **When** 방문자가 홈페이지를 조회하면, **Then** 새 이미지는 표시되지 않는다.
3. **Given** 대체 텍스트가 있는 대표 이미지 초안, **When** 관리자가 게시하면, **Then** 방문자는 새 대표 이미지를 볼 수 있다.
4. **Given** 대표 이미지를 교체함, **When** 이전 이미지가 초안·게시본·버전 기록 어디에서도 참조되지 않으면, **Then** 이전 객체를 안전하게 정리할 수 있다.

---

### User Story 3 - 운영자가 안전하게 활성화하고 되돌린다 (Priority: P2)

운영자는 정책 검증 후 저장 기능을 활성화하고, 장애 시 새 업로드만 즉시 중단할 수 있다.

**Why this priority**: 기능 플래그만 켜는 배포는 권한 또는 데이터 정합성 결함을 운영 환경에 노출할 수 있다.

**Independent Test**: 활성화 전후의 업로드 동작과 비활성화 후의 조회·업로드 동작을 운영 체크리스트대로 확인한다.

**Acceptance Scenarios**:

1. **Given** 정책과 버킷이 아직 적용되지 않음, **When** 저장 기능이 비활성 상태이면, **Then** 원격 업로드를 시도하지 않는다.
2. **Given** 정책 검증이 완료됨, **When** 운영 환경에서 저장 기능을 활성화하면, **Then** 관리자 업로드와 공개 이미지 조회가 정상 동작한다.
3. **Given** Storage 장애 또는 정책 이상, **When** 운영자가 저장 기능을 비활성화해 재배포하면, **Then** 새 업로드는 중단되고 기존 데이터는 삭제되지 않는다.

### Edge Cases

- 허용하지 않은 형식, 내용과 MIME 유형이 다른 파일, 빈 파일, 20MB 초과 파일은 저장하지 않는다.
- 한 번에 20장 또는 사례당 69장을 초과하면 해당 선택을 저장하지 않는다.
- 원본 저장 후 검토본 저장이 실패하면 원본을 정리하고 실패 상태를 표시한다.
- 파일 저장 후 사진 정보 저장이 실패하면 새로 만든 Storage 객체를 정리한다.
- 객체 삭제가 실패하면 사진 정보를 먼저 삭제해 고아 객체를 숨기지 않고, 관리자에게 재시도 가능한 오류를 표시한다.
- 공개 사진이 비공개로 전환되거나 사례가 비공개·삭제 상태가 되면 새 조회 주소를 발급하지 않는다.
- 이미 발급된 제한 시간 주소는 만료될 때까지 유효할 수 있으므로 짧은 만료 시간을 유지한다.
- 대표 이미지 교체 시 게시본이나 버전 기록이 이전 객체를 참조하면 즉시 삭제하지 않는다.

## Requirements

### Functional Requirements

- **FR-001**: 시스템은 활성 관리자에게만 이미지 업로드·교체·삭제 권한을 부여해야 한다.
- **FR-002**: 시스템은 사례 원본을 공개 검토본과 분리하여 비공개로 보관해야 한다.
- **FR-003**: 시스템은 공개 검토본을 재인코딩하여 원본 메타데이터를 제거해야 한다.
- **FR-004**: 공식 관리자 업로드 UI는 실제 파일 서명이 선언 형식과 일치하는 JPG, PNG, WebP 입력과 20MB 이하 파일만 허용하고, Storage 버킷은 선언 MIME과 크기를 재검증하며 공개 검토본은 WebP만 허용해야 한다. HEIC/HEIF와 신뢰 경계를 우회한 실제 바이트 판별은 서버 처리 경계가 추가될 때까지 지원 범위에서 제외한다.
- **FR-005**: 시스템은 사례 업로드를 회당 20장, 사례당 69장 이하로 제한해야 한다.
- **FR-006**: 시스템은 게시 사례에 연결된 공개·준비 완료 사진에만 방문자 조회 권한을 부여해야 한다.
- **FR-007**: 시스템은 사례 원본을 방문자와 일반 고객에게 공개해서는 안 된다.
- **FR-008**: 시스템은 랜딩 대표 이미지를 실제 저장하고 초안과 게시본을 구분해야 한다.
- **FR-009**: 시스템은 게시된 랜딩 대표 이미지만 방문자에게 노출해야 한다.
- **FR-010**: 시스템은 업로드 또는 메타데이터 저장의 일부 단계가 실패하면 해당 작업에서 새로 생성한 객체를 정리해야 한다.
- **FR-011**: 시스템은 사진 삭제 시 데이터와 원본·검토본 객체의 결과를 일관되게 처리하고 실패를 관리자에게 알려야 한다.
- **FR-012**: 시스템은 기능 플래그가 비활성일 때 새 원격 업로드와 삭제 요청을 수행하지 않아야 한다.
- **FR-013**: 운영 문서는 정책 적용, 검증, 활성화, 롤백 순서를 제공해야 한다.
- **FR-014**: 실제 비밀번호와 관리자용 비밀 키는 브라우저 환경변수, 소스 코드, 로그에 포함되어서는 안 된다.

### Key Entities

- **사례 이미지 원본**: 관리자만 접근 가능한 업로드 원본과 사례 식별 경로를 가진다.
- **사례 이미지 검토본**: 공개 가능하도록 재인코딩된 파일이며 사진 공개 상태와 사례 게시 상태에 연결된다.
- **랜딩 대표 이미지**: 초안 또는 게시본에서 참조되는 대표 이미지와 대체 텍스트를 가진다.
- **이미지 참조**: 데이터 레코드와 Storage 객체를 연결하며 공개 여부와 삭제 가능 여부 판단의 기준이 된다.

## Success Criteria

### Measurable Outcomes

- **SC-001**: 허용되지 않은 사용자의 업로드·원본 조회·삭제 시도 100%가 거부된다.
- **SC-002**: 비공개 사례 또는 비공개 사진에 대한 방문자 조회 시도 100%가 실패한다.
- **SC-003**: 허용된 사례 이미지 업로드는 원본·검토본·사진 정보 세 항목을 모두 저장하거나 새로 만든 항목을 모두 정리한다.
- **SC-004**: 대표 이미지가 게시되기 전에는 공개 화면 노출 건수가 0건이고, 게시 후에는 1분 이내 공개 화면에 반영된다.
- **SC-005**: 제한 위반 파일은 원격 저장 요청 없이 100% 차단된다.
- **SC-006**: 운영 체크리스트의 권한·업로드·게시·삭제·롤백 시나리오가 모두 통과한다.

## Assumptions

- 기존 Supabase Auth 역할과 활성 관리자 판정을 그대로 사용한다.
- 운영 저장 기능은 사용자가 승인했으며, 활성화 플래그는 정책 적용과 검증이 끝난 뒤 Vercel에서 설정한다.
- 사례 사진을 개별 삭제하면 원본과 검토본도 즉시 삭제한다.
- 사례 자체의 소프트 삭제는 복구 가능성을 위해 객체를 즉시 삭제하지 않지만 새 공개 주소 발급은 중단한다.
- 랜딩 이미지 교체본은 초안·게시본·버전 기록의 참조가 사라진 뒤에만 정리한다.
- Storage API를 통해 객체를 삭제하며 Storage 메타데이터 테이블을 직접 삭제하지 않는다.
